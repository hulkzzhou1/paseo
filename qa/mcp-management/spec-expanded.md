# MCP 服务统一管理：手动服务增删改与启停，仅保留设置入口

状态：产品范围及测试边界已获用户确认，可进入实现。现有代码只是未验证草稿。

## Problem Statement

目前 MCP 页面只展示插件注册的服务，用户无法直接添加自己的 MCP 服务，也无法编辑、删除或停用手动服务。主页面侧边栏与设置同时提供 MCP 入口，造成导航重复。“没有已注册的插件 MCP 服务”也错误地将页面限定为插件能力。

用户需要在当前主机的设置中统一查看 MCP 服务，并管理手动服务，同时保留插件对自身服务配置和生命周期的所有权。

## Solution

设置中的 MCP 页面成为唯一的 MCP 管理入口。移除主页面侧边栏及其自定义导航选项中的 MCP 项；保留设置入口及已有 MCP 设置页路由。空状态统一为“没有已注册的 MCP 服务”。

页面统一展示手动服务和插件服务，清楚区分来源。手动服务支持新增、编辑、删除、启用和停用，并覆盖 stdio、HTTP（Streamable HTTP）和 SSE。停用保留配置，删除需用户确认。插件服务通过所属插件配置入口管理，随插件生命周期撤销，统一页面不直接覆盖插件配置。

配置按主机隔离，供该主机支持相应传输的 provider 使用。保存只做配置校验和持久化；provider 在新建或实际重新建立 Agent 运行实例时连接当前启用服务。Paseo daemon 不充当 MCP 代理，不主动中断或刷新现有 Agent。

系统 MCP 同时提供管理工具，让 Agent 查看当前 host 的服务摘要，并新增、编辑、启停和删除手动服务。工具复用 UI 的配置与生命周期规则；插件服务只能查看来源，不能通过这些工具覆盖配置或撤销。

## User Stories

1. 作为用户，我希望只在设置中进入 MCP 管理，以避免主页面出现重复入口。
2. 作为用户，我希望已有 MCP 设置页链接继续可用，以保持导航连贯。
3. 作为用户，我希望在同一页面看到手动服务与插件服务，以了解当前主机可提供的 MCP 能力来源。
4. 作为用户，我希望看清每项服务的来源和传输方式，以选择正确的配置入口。
5. 作为用户，我希望没有任何服务时看到“没有已注册的 MCP 服务”，以理解该页面不限于插件服务。
6. 作为用户，我希望添加 stdio 服务并填写命令、参数及环境变量，以使用本机 MCP 程序。
7. 作为用户，我希望添加 HTTP 服务并填写 URL 和所需请求头，以接入远程 MCP 服务。
8. 作为用户，我希望添加 SSE 服务，以连接已有 SSE MCP 服务。
9. 作为用户，我希望编辑手动服务配置，以更新启动参数、地址和凭据。
10. 作为用户，我希望无效配置在保存前得到清楚反馈，以避免保存无法使用的定义。
11. 作为用户，我希望保存失败时保留输入并显示失败，以便修正或重试。
12. 作为用户，我希望提交期间有明确状态并防止重复提交，以避免重复服务或重复操作。
13. 作为用户，我希望停用手动服务而保留配置，以暂时停止向新的 Agent 连接提供它。
14. 作为用户，我希望重新启用服务时复用保存的配置，以免重复输入。
15. 作为用户，我希望删除前确认，取消时保留服务，确认后移除配置，以避免误删。
16. 作为用户，我希望 daemon 重启后保留服务配置及启用状态，以维持设置。
17. 作为用户，我希望只向当前主机保存服务，以避免把本机命令或凭据送到其他主机。
18. 作为用户，我希望切换主机或重连时不显示旧主机的数据，以避免误操作。
19. 作为用户，我希望通过插件自己的配置入口修改插件服务，以避免插件重载覆盖手动改动。
20. 作为用户，我希望插件卸载或服务撤销后不再向新的 Agent 连接提供其配置，以保持生命周期一致。
21. 作为用户，我希望新建和实际重新建立的 Agent 连接使用当前启用配置，以使编辑、停用、删除生效。
22. 作为用户，我希望正在运行的 Agent 不被设置修改中断，以继续当前工作。
23. 作为用户，我希望添加和保存不会立即启动本地进程或访问远程服务，以区分保存配置与建立连接。
24. 作为用户，我希望 provider 不支持服务所需传输或配置时得到明确错误，以免服务被静默忽略。
25. 作为用户，我希望手机宽度、触摸及键盘操作都能完成管理，以跨设备使用该功能。
26. 作为用户，我希望凭据不会出现在服务列表、普通错误或日志中，以避免配置泄露。
27. 作为旧客户端用户，我希望协议仍可解析新 daemon 的消息；作为新客户端用户，我希望旧主机明确提示升级，以避免误以为新功能已可用。

28. 作为 Agent 用户，我希望系统 MCP 能发现并调用 MCP 服务管理工具，以通过对话完成与设置页一致的手动服务管理。
29. 作为用户，我希望工具返回值只包含安全摘要，不能把现有凭据带入 Agent 上下文；编辑未提供的连接配置时保留原值。

30. 作为用户，我希望手动服务支持表单／JSON 两种编辑模式，以粘贴或直接编辑单个服务的连接配置，切换模式不丢失草稿。

## Implementation Decisions

- 复用现有 host Settings、服务列表、配置持久化、配置变更通知和 provider 启动适配。不要构建独立 MCP 代理、连接池或新测试框架。
- 手动服务与插件服务是不同所有权来源。手动服务的配置与启用状态属于主机；插件服务定义属于插件安装实例，统一页面只显示其摘要和可用配置入口。
- 新增的启停管理属于手动服务。插件继续通过自身配置及生命周期控制服务；没有插件配置入口时不要伪造可编辑按钮或替插件提供通用覆盖配置。
- 手动服务有稳定身份、可辨识名称、连接定义及启用状态。新增默认启用；命名或来源冲突必须明确拒绝，不能覆盖同名插件、平台或 Agent 自带 MCP 定义。
- stdio 配置表达命令、参数和环境变量；HTTP/SSE 表达 URL 和请求头。不要引入未确认的 provider 特有选项。合法性校验不等同于服务可达性或认证成功。
- 停用保留定义，启用恢复分发；删除在确认后移除定义。单项修改不得误删其他服务；切换传输方式或删除字段后不能残留旧传输的参数或凭据。
- 配置中的凭据仅由现有受信任配置访问路径读取并传给需要它的 provider；列表摘要、普通日志、错误及验收材料不包含秘密值。延续现有权限模型，不新增用户鉴权体系。
- provider 直接连接当前启用的手动及插件服务。保持既有平台工具与 Agent 自带 MCP 配置；撤销的主机服务不得从旧 Agent 持久化快照复活。
- 新建或实际重新建立运行实例时采用最新配置。不主动刷新工具列表、重启 Agent、断开已有连接，也不宣称停用会立即结束运行中的服务进程。
- 配置在保存时不触发 stdio 启动或远程连接。stdio 命令运行于目标 daemon/provider 所在机器，不运行于操作设置的手机或桌面客户端。
- 页面查询和操作绑定真实 host 身份。离线、加载、失败和已加载但为空分别呈现；迟到响应不能污染另一主机。后台刷新不能销毁正在编辑的表单。
- 手动服务新增和编辑提供表单／JSON 模式，JSON 对象只表达该服务的连接定义（type 及对应字段），名称与启用状态保持外层所有权。复用现有 schema 和同一表单模型，不新增编辑器依赖或整库导入导出。合法配置在两种模式间往返保持一致；无效 JSON 保留原文并展示错误，不允许保存或无提示切换丢弃。后台刷新及保存失败保留当前模式与输入；删除字段和切换传输后不残留旧配置。
- 沿用现有表单模型、设置组件、确认弹窗及移动布局惯例。保存、启停、删除均有 pending、成功与失败反馈。
- 新功能在主机能力入口统一 gating；新协议字段保持可选，旧消息可解析。旧主机提示升级，不模拟功能降级或静默成功。
- 移除主侧栏 MCP 项时兼容已经保存的侧栏偏好，不影响其他项目顺序和可见性；更新原先依赖该入口的测试。
- 系统 MCP 工具复用既有平台工具目录和配置存储，建议 `list_mcp_services`、`create_mcp_service`、`update_mcp_service`、`set_mcp_service_enabled`、`delete_mcp_service`，最终命名遵循现有目录风格。工具作用于所连接 daemon 的 host，不新增跨 host 代理路径。沿用既有工具策略和调用边界，不另建鉴权体系。
- 列表及写操作结果仅返回稳定身份、名称、来源、传输和启用／注册状态，不返回命令、参数、环境变量、URL 或请求头的私密配置。更新只修改显式提供的字段；提供连接定义时按完整定义替换，未提供则保留。错误不回显凭据。插件拥有的服务写入、未知 ID 和重复名称明确失败。
- MCP 删除使用显式确认参数并声明破坏性语义；未确认不删除。启停沿用同一持久化语义。保存和工具发现都不建立所管理 MCP 的连接。
- 本规格是插件 MCP 服务注册规格的后续扩展，替代其“主侧栏 MCP 入口”和“只展示插件服务”的范围；插件注册 API、UI RPC 和 provider 直连原则保持。

## Testing Decisions

用户已确认以下边界；仅测试外部行为，优先使用现有最高层接缝：

1. **隔离 daemon + 真实客户端**：沿用现有插件服务端到端测试，验证手动服务新增、编辑、删除、启停、重载／重启持久化、主机隔离，以及新建／重建运行实例的配置分发。使用临时目录、虚构配置和现有可观察 provider 接缝，不启动真实用户 MCP 或修改生产配置。验证保存本身不建立连接、禁用／删除后不从快照复活、同名来源不被覆盖、插件注册与 UI RPC 不回归。
2. **现有浏览器验收**：通过设置进入页面，覆盖主侧栏入口移除、增删改启停、删除取消、通用空状态、插件配置跳转、离线和失败反馈、host 切换及迟到响应、后台刷新不丢编辑状态。包括桌面和手机宽度、触摸及键盘操作，复用现有浏览器套件。JSON 模式额外覆盖三种连接配置、模式往返、语法／schema 错误、保存失败和后台刷新保持草稿；需要时使用同一表单模型接缝补齐浏览器无法有效覆盖的转换边界。
3. **现有 provider 适配测试**：按实际传输支持验证配置分发及不支持场景明确失败。沿用已有真实 MCP 验收模式，不重复真实模型调用。只有测试现有接缝无法覆盖的配置持久化／表单校验时，才补针对性下层测试。
4. **系统 MCP 管理工具**：在现有隔离 daemon 和真实 MCP 客户端接缝验证 `tools/list` 可发现、`tools/call` 增改启停删除、未确认删除拒绝、插件写入拒绝、未知 ID／重名／无效输入、安全摘要和错误脱敏、两台 host 隔离，以及变更能被 UI 所用配置 API 读取。无需真实模型或新增框架；保留已有原生平台工具目录策略。
5. 在本次最终代码版本运行类型检查、lint、格式检查和修改范围内的针对性测试；先构建跨工作区声明。记录版本、命令、完成退出码和日志。禁止以主线旧 CI 结果替代本次验收，不跑全套本地测试。
6. 浏览器手机宽度不等于原生手机或 Electron 验收；未执行的平台单独记录。当前生产 fork 预发布版及用户现有 macOS 客户端都不包含本次新增管理功能。

## Out of Scope

- MCP 连接测试、工具列表浏览和逐 Agent 授权。
- daemon MCP 代理、宿主 UI MCP 客户端、RPC 自动转 MCP tools、有界发现框架。
- 主动重启或刷新现有 Agent、强制切断已有服务连接。
- 统一页面直接改写或删除插件拥有的服务配置、替插件维持第二份配置。
- 工蜂插件适配实现（由其项目 Agent 独立推进）。
- 发布 macOS／移动客户端安装包、发布新版本或更新生产 daemon；这些作为后续交付任务另行授权。
